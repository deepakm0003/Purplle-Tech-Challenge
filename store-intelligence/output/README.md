# Pipeline output directory

Generated by the CCTV detection pipeline. **Committed copies** for reviewers also live under `data/bootstrap/` (events) and `data/submission/` (merged files).

## How files are created

```powershell
cd store-intelligence
python scripts/process_stores.py --export-tracks
python scripts/backfill_entry_events.py
python scripts/build_submission_events.py
python scripts/sync_bootstrap_events.py
```

## Directory map

| Path | Description |
|------|-------------|
| `store-1/events/*.jsonl` | Per-camera behavioural events — Store 1 (`ST1008`) |
| `store-2/events/*.jsonl` | Per-camera events — Store 2 (`ST2002`) |
| `store-1/tracks/*_tracks.json` | Frame-level bounding boxes for dashboard CCTV overlay |
| `store-2/tracks/*_tracks.json` | Same for Store 2 |
| `submission_events.jsonl` | **All stores merged** — challenge `Event` schema (ingest into API) |
| `sample_format_events.jsonl` | Same events in `sample_eventsbe42122.jsonl` shape |

## Per-camera event files (Store 1)

| File | Camera | Role |
|------|--------|------|
| `CAM_3_-_entry_events.jsonl` | CAM 3 | Entry / exit |
| `CAM_1_-_zone_events.jsonl` | CAM 1 | Main floor zone |
| `CAM_2_-_zone_events.jsonl` | CAM 2 | Main floor zone |
| `CAM_5_-_billing_events.jsonl` | CAM 5 | Billing |

## Per-camera event files (Store 2)

| File | Camera | Role |
|------|--------|------|
| `entry_1_events.jsonl` | Entry 1 | Entry |
| `entry_2_events.jsonl` | Entry 2 | Entry |
| `zone_events.jsonl` | Zone | Main floor |
| `billing_area_events.jsonl` | Billing | Billing queue |

## Event line format (one JSON object per line)

```json
{
  "event_id": "uuid",
  "store_id": "ST1008",
  "camera_id": "CAM-ENTRY",
  "visitor_id": "VIS_abc123",
  "event_type": "ENTRY",
  "timestamp": "2026-06-04T10:00:00Z",
  "zone_id": "ENTRY",
  "dwell_ms": 0,
  "is_staff": false,
  "confidence": 0.85,
  "metadata": { "queue_depth": null, "sku_zone": null, "session_seq": 1 }
}
```

## API usage

```powershell
# Ingest merged file
curl -X POST http://localhost:8000/api/analytics/events/ingest `
  -H "Content-Type: application/json" `
  -d "{\"events\": [<paste or use ingest script>]}"
```

Or rely on startup bootstrap from `data/bootstrap/` (same event content).

## Git note

`output/` is regenerated locally when you re-run the pipeline. Committed snapshots: `data/bootstrap/`, `data/submission/`, and this folder when pushed to GitHub.
